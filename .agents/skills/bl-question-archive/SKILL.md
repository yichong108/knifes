# bl-question-archive

把**当前会话里已形成的结论/要点**整理成一段归档文字，写入 `问题系统` 里对应的问题文档；必要时同步更新问题列表的状态与备注。

## 目标文件

| 用途 | 路径 |
| --- | --- |
| 问题列表 | `问题系统/问题列表.md` |
| 问题详情 | `问题系统/问题/<问题名称>.md` |

## 何时启用

出现以下任一信号时启用（本 skill 默认需点名或明确触发词）：

- 「归档」「总结归档」「把这次写回文档」
- 明确点名 `bl-question-archive`
- 要把本轮讨论结论落到某个问题 md

## Workflow

- [ ] 读取 `问题系统/问题列表.md`，对照当前对话推断目标问题
- [ ] **目标不确定 → 停下来问用户**（见下方规则）；确定后再继续
- [ ] 总结当前上下文为归档正文（见「总结要求」）
- [ ] 追加写入对应 `问题系统/问题/<问题名称>.md`
- [ ] 更新 `问题列表.md` 该行的备注（及按需改状态）
- [ ] 简短告知用户：写到了哪个文件、改了什么

### 1. 选定目标文档（硬性）

1. 先读 `问题系统/问题列表.md`。
2. 用对话主题、用户点名的问题名、最近在讨论的问题，匹配列表中的某一行。
3. **以下任一情况必须先问用户，不得猜测落盘：**
   - 列表里有多个候选都说得通
   - 对话主题与列表中任何问题都对不上
   - 用户只说「归档」但未指明问题，且会话里也看不出唯一目标
   - 详情文件不存在，或同名歧义
4. 提问要短：列出候选链接/名称（1–3 个），或请用户给出问题名；**每轮只问这一件事**，等确认后再写文件。
5. 若用户指定了尚未建档的问题：先按 `bl-question-create` 建列表行 + 空详情 md，再归档；不要 silently 新建无关文件。

### 2. 总结要求

从当前对话提炼，**只写已达成的共识与可复用结论**，不要整段粘贴聊天记录。

- 语言：中文；简洁、可日后回看
- 去掉客套、过程性试错、已否决方案的细节（除非否决本身是结论）
- 保留：问题是什么、关键结论、取舍理由、可执行要点、未决事项（若有）
- 长度：通常半页以内；信息多时用小标题 / 列表 / 表格，风格对齐该问题文档已有归档块

### 3. 写入详情文档

打开 `问题系统/问题/<问题名称>.md`：

1. 在文末追加（已有正文与归档块之间用 `---` 分隔；若文末已有 `---` 则不再重复）。
2. 标题按归档范围选用：

| 范围 | 标题模板 |
| --- | --- |
| 整题/整条问题收束 | `## 归档（YYYY-MM-DD）` |
| 某一子题/某一问 | `## 第 N 题归档（YYYY-MM-DD）` 或 `## <子题短名>归档（YYYY-MM-DD）` |

日期为当天 `YYYY-MM-DD`。

3. 标题下写总结正文；不要覆盖或改写既有归档块，只追加。
4. 不要改文档开头的 `# 标题` 与用户原有正文结构（除非用户明确要求整理）。

**整题归档示例：**

```markdown
---

## 归档（2026-08-21）

（总结正文）
```

**子题归档示例：**

```markdown
---

## 第 1 题归档（2026-08-21）

### 小节标题
（总结正文）
```

### 4. 更新问题列表

在 `问题系统/问题列表.md` 找到对应行，只改该行，不改其他行：

| 情况 | 状态 | 备注 |
| --- | --- | --- |
| 整题已收束、可视为完成 | 改为 `[x]` | `已归档：` + 一句极短摘要（约十字内） |
| 仅部分子题归档 | 保持原状态（通常仍 `[ ]`） | `第N题已归档（短摘要）`；可与原有备注合并，勿删掉仍有用的旧备注 |

备注要短，详情留在问题 md 里。

### 5. 收尾回复

用几句话告诉用户：

- 归档到了哪个问题文件
- 列表备注/状态是否已改
- 若仍有未决点，点一句即可

## 禁止

- 目标文档未确认时擅自写入
- 用聊天全文或无结构长文冒充归档
- 覆盖已有归档章节
- 改动无关问题行或无关文件
- 擅自 `git commit` / `push`（除非用户另有要求）

## 与 bl-question-create 的关系

- **新建问题条目** → `bl-question-create`
- **把讨论结论写入已有（或刚建好的）问题文档** → 本 skill
- 归档时发现还没有对应条目：先 create，再 archive
