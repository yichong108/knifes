# Concept 参考

`SKILL.md` 放流程与输出骨架；本文件补充各层写作标准、立场方提示、澄清示例与反例。

## 各层写作标准

| 层 | 必须回答 | 写好的标准 | 常见失败 |
|----|----------|------------|----------|
| 背景起源 | 从哪来、在什么语境出现、为何要被命名 | 能让读者感到「当时缺一块名字/框架」 | 只堆年份人名，不说「为何需要这个词」 |
| 解决什么问题 | 痛点是什么；有/无对比 | 读者能复述「没有它会怎样」 | 只写「很重要」「提升效率」而无对照 |
| 定义多维解释 | ≥2 个可区分的维度 | 各维度视角不同，不是同义反复 | 百科单句定义复制粘贴；维度名不同内容相同 |
| 各方立场与利弊 | 2–4 个具体相关方 + 如何看待 + 利弊成因 | 每条利弊有「为何如此」 | 「有人支持有人反对」；只报结果不说机制 |

### 第 3 层：可用维度（按概念选用，不必全用）

- **形式定义**：教科书/规范里怎么写
- **操作定义**：在实践中如何识别、测量或判定「算不算它」
- **类比**：用更熟的对象对照（点明类比边界）
- **边界 / 非定义**：容易混淆的相邻概念；它**不是**什么
- **演化定义**：早期含义 vs 当前常见用法（若差异大）

### 第 4 层：利弊成因

与 choice 的「为何会出现」同构：结果 + 一句机制。

**好：**

- 利：监管方可审计 —— **为何如此**：概念要求留痕与可追溯字段，检查时有固定抓手
- 弊：一线执行成本上升 —— **为何如此**：每次操作多出校验与记录步骤，吞吐下降

**差：**

- 「对监管有利，对执行有弊」
- 「存在争议」
- 「需权衡利弊」（无相关方、无机制）

## 常见立场方（选用，非强制全列）

按概念挑选 2–4 个**真实相关**的即可：

| 类型 | 可能关心什么 |
|------|----------------|
| 提出者 / 设计者 | 意图是否被正确理解、是否被滥用 |
| 使用者 / 消费者 | 是否更好用、成本是否转嫁到自己 |
| 维护者 / 运营者 | 复杂度、稳定性、长期负担 |
| 既得利益者 | 旧秩序是否被削弱、护城河是否变化 |
| 后来者 / 接手者 | 学习成本、历史包袱 |
| 监管 / 合规方 | 可审计性、责任归属 |
| 批评者 / 怀疑者 | 概念是否空洞、是否掩盖真实问题 |
| 平台 / 中介方 | 标准是否强化其中心地位 |

禁止虚构与概念无关的「通用群众」凑数。

## 澄清问题示例（开场最多 1 题）

仅当所指不清时使用；对齐后立刻进入四层，不要继续追问。

| 模糊点 | 示例问题 |
|--------|----------|
| 同名多义 | 「你说的 agent，更接近 AI 自主代理、软件里的代理模式，还是商务/法律代理？」 |
| 缺领域 | 「你想在软件工程语境下理解『抽象』，还是哲学/日常用语？」 |
| 过宽 | 「你更想先弄清『微服务』这个架构概念本身，还是你们团队文档里特指的那套实践？」 |
| 缩写不明 | 「这里的 CI 是 Continuous Integration，还是你们内部另一个缩写？」 |

### 澄清反例

- 一次抛出多个澄清问题
- 所指已清仍先「采访」用户背景
- 澄清后不讲四层，改成苏格拉底连环问

## 交付自检

写完后快速过一遍：

- [ ] 四层标题齐全且顺序正确
- [ ] 第 2 层有「没有它时 / 有了它之后」对照
- [ ] 第 3 层 ≥2 个维度，且互不重复
- [ ] 第 4 层相关方具体；每条利/弊有「为何如此」
- [ ] 有理解检查清单（3–5 条）
- [ ] 未擅自写成决策方案对比（那是 choice）

## 与 choice 的边界

| 用户意图 | 用哪个 |
|----------|--------|
| 弄清概念是什么、从哪来、谁怎么看 | **concept** |
| 要不要做、选 A 还是 B、风险大不大 | **choice** |
| 先理解再决策 | 先 concept 讲清，再在用户进入取舍时用 choice |

## 话术边界

- 可以：多维定义、历史语境、多方利弊与成因、标明常见分歧
- 不要：假装唯一标准答案；用恐吓或鸡汤代替机制；把讲解偷换成实施方案清单
- 涉及法律/医疗/投资等专业结论时：标明非正式理解辅助，引导寻求合格专业意见，同时仍把概念结构讲清
