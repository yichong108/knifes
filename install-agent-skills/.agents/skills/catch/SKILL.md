# Catch

把「哪里不对劲」说清楚：系统化扫描检查对象，列出**有证据支撑**的问题，标严重度，给可执行的下一步——**不替用户做最终决策**。

与 `choice` 互补：catch 负责发现问题；需要取舍时用 choice。  
与 `concept` 互补：用户要「讲透概念」时用 concept；catch 只标理解缺口类问题。

## 何时启用

出现以下任一信号时启用，即使未被点名：

- 「发现问题 / 找问题 / 哪里有问题 / 有哪些坑」
- 「排查 / 体检 / 审计 / 挑毛病 / 风险扫描」
- 用户描述现状、方案、流程或材料，但说不清症结，需要结构化梳理

## Workflow

- [ ] 明确检查对象（查什么、依据哪些材料）
- [ ] 收集可用上下文（用户输入、文件、对话历史）
- [ ] 按发现透镜扫描
- [ ] 区分事实与推断（有证据 → 问题；缺证据 → 待确认）
- [ ] 按模板输出清单；必要时提示可衔接 choice / concept

### 1. 明确检查对象

用 1–2 句界定：在查什么（项目、方案、流程、文档、现状描述等），依据哪些材料。

信息极少、对象不清时：**最多问 1 个**对齐对象的问题，然后基于现有信息出清单，并在「待确认」中标明假设。禁止问卷式长探询。

### 2. 收集上下文

从以下来源读取，不臆造未给出的信息：

- 用户当前消息与对话历史
- 用户 @ 或打开的文件、目录
- 可观察的事实（配置、日志、结构等）

### 3. 发现透镜（摘要）

按以下维度扫描；细则与示例见 [references/REFERENCE.md](references/REFERENCE.md)：

| 透镜 | 问什么 |
|------|--------|
| 症状 vs 根因 | 表面现象背后是否还有更底层矛盾 |
| 假设与缺口 | 哪些前提未验证、关键信息缺失 |
| 矛盾与不一致 | 说法、数据、目标之间是否打架 |
| 利益方盲区 | 谁被忽略、谁承担未说清的风险 |
| 失败模式 | 什么情况下会翻车、有无单点故障 |
| 依赖与约束 | 隐藏依赖、资源/时间/权限是否不匹配 |

### 4. 区分事实与推断

- **问题清单**：每条必须有**证据**（用户原话、文件片段、可观察事实）
- **待确认 / 假设**：缺证据但值得验证的点，不得冒充已证实问题

## 输出结构（必须）

按此结构回复；可按场景删减「暂未发现问题的方面」，但**不得省略证据与严重度**：

```markdown
## 检查对象
（1–2 句：查什么、依据哪些材料）

## 问题清单
### 问题 1：…
- **严重度**：🔴 高 / 🟡 中 / 🟢 低
- **证据**：…
- **影响**：…
- **建议下一步**：…

（按严重度从高到低排列）

## 待确认 / 假设
- …（缺证据但值得验证的点；无则写「无」）

## 暂未发现问题的方面
- …（已检查且目前无明显问题的维度；可选）
```

问题按严重度 **🔴 → 🟡 → 🟢** 排列。

## 严重度约定

| 级别 | 含义 | 标注要求 |
|------|------|----------|
| 🔴 高 | 易造成重大损害或难逆后果 | 写清触发条件与影响范围 |
| 🟡 中 | 有实质代价，通常可缓解 | 写清影响与可缓解方向 |
| 🟢 低 | 摩擦/体验/可维护性问题为主 | 一句话影响即可 |

禁止空话（「有风险请谨慎」「可能有问题」）而不写证据与影响。

## 行为准则

1. **证据优先**：每条问题必须有证据；无证据归入「待确认」，不得臆造。
2. **只发现问题**：不展开完整方案；「建议下一步」可执行但简短（如「补备份再迁移」「对齐 XX 与 YY 的目标」）。
3. **不问卷式探询**：缺对象时最多 1 问，然后出清单并标假设。
4. **与 choice 分界**：用户问「选哪个 / 要不要做」时，简短说明可改用 choice；本 skill 不输出方案对比与默认推荐。
5. **与 concept 分界**：用户要深入理解某概念时用 concept；catch 只标「理解缺口」类问题，不展开四层讲解。
6. **区分事实与判断**：已知事实、推断、假设分开写。
7. **语言**：中文、短句；严重度 emoji 与 choice 一致。

## Examples

**Example 1 — 方案描述**

- Input: 「帮我看看这个上线方案有什么问题：[方案要点…]」
- Output: 检查对象 + 按透镜列问题（如回滚未定义、监控缺口）+ 证据引用原方案 + 严重度 + 建议下一步

**Example 2 — 信息极少**

- Input: 「帮我排查一下团队协作有什么问题」
- Output: 最多 1 问对齐范围（或基于常见协作维度出清单）；缺口写入「待确认」
