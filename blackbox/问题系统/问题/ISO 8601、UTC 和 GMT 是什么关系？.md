# ISO 8601、UTC 和 GMT 是什么关系？

---

## 归档（2026-08-25）

本轮问答：日志时间 `2026-08-25T04:43:55.921Z` 是什么格式 → ISO 8601 是否等于 UTC → GMT 是否过时。

### 结论

这条字符串同时符合 **ISO 8601** 和 **RFC 3339**，时区是 **UTC**（`Z` = 零时区）。对中国（UTC+8）是当天 **12:43:55.921**。

三件事不要混：

| 名称 | 管什么 | 现在的地位 |
| --- | --- | --- |
| **UTC** | 世界对时用的公共钟 | 现行国际时间基准 |
| **ISO 8601** | 时刻怎么写成字符串 | 写法标准；可以是 `Z`，也可以是 `+08:00` |
| **RFC 3339** | 给互联网用的 ISO 8601 子集 | 日志 / JSON 常用这一套 |
| **GMT** | 旧世界钟的名字 | 作为标准钟已过时；口语里常被当成 UTC |

### Q1：`2026-08-25T04:43:55.921Z` 是什么？

| 部分 | 含义 |
| --- | --- |
| `2026-08-25` | 年-月-日 |
| `T` | 日期和时刻的分隔符 |
| `04:43:55.921` | 时:分:秒.毫秒 |
| `Z` | Zulu time，即 UTC+0 |

ISO 8601 是写法标准，合法形式很多；RFC 3339 从中挑出更严、更好解析的子集。带 `T`、带 `Z` 或 `+08:00` 的这种字符串，日常说「ISO 时间」或「RFC 3339 时间」多半就是它。

### Q2：国际标准是 UTC（零时区）吗？

**对时基准是 UTC；写法标准是 ISO 8601。** 不是一回事。

- UTC 回答：现在几点（按世界公共钟）。
- ISO 8601 回答：这个时刻写成字符串长什么样。
- `Z` 只表示「这条按 UTC 写」；ISO 8601 并不强制全世界都显示零时区。

国际标准要求有共同原点，不要求中国人看电脑都显示 `04:43`。常见做法：系统存 UTC，界面显示本地时间。

### Q3：GMT 过时了吗？

**作为世界标准钟：过时了，现行的是 UTC。**  
**作为口头禅和时区标签：还在用**，多半等于「UTC / 零时区」。

GMT 来自格林尼治天文台的平均太阳时。地球自转不均匀后，改用原子钟维护的 UTC。日常软件、航空、时区列表仍写 `GMT`、`GMT+8`，通常就是 UTC / UTC+8。较真（日志、协议、计量）写 UTC。

`Z` 在标准里表示 UTC；历史上也叫 Zulu，对应旧军语里的 GMT 零时区。GMT 和 UTC 都是零时区附近，**不是**和北京时间差 8 小时——差 8 小时的是 UTC+8（旧称 GMT+8）。

英国冬令时仍常叫 GMT，夏令时是 BST（UTC+1），所以「伦敦现在 = GMT」夏天不成立。

### 理解要点

- 日志里的 `…Z`：ISO 8601 / RFC 3339 格式的 UTC 时间。
- UTC 是钟；ISO 8601 是写法；RFC 3339 是给网络用的那种子集。
- GMT 当标准钟已过时；当别名仍等于 UTC。
- 看中国墙上钟：把 `Z` 时间加 8 小时。
